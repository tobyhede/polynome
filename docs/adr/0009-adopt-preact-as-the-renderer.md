# Adopt Preact as the renderer

Polynome will render the cycles and preset regions through Preact, written with `htm` tagged templates rather than JSX and served without a development build. Preact is adopted as a renderer only: interface state stays in module scope, and the visual playhead and the beat-grouping measurement keep their imperative access to the DOM. This supersedes ADR-0003 only where that decision rejected the design prototype's React runtime, and amends the zero-runtime-dependency position recorded in `AGENTS.md`; every other consequence in ADR-0003 remains in force. ADR-0004 and ADR-0006 each restate that position in passing while deciding something else, and both are left as written — they record what was true when they were taken, and this decision is where the change is read from.

The reason recorded below for rejecting JSX is amended by
[ADR-0018](0018-strip-types-in-the-development-server.md), which is where that
change is read from. `server.ts` — `server.mjs` when this was written — now
strips TypeScript annotations from every module it serves, so "served without a
development build" above is a claim about a bundle and an artifact rather than
about bytes reaching the browser unmodified. Preact through `htm` is unchanged
and every other consequence below remains in force.

The port was written before ADR-0008 replaced amplitude levels with Step voices and before both Meter components became selects, and was rebased onto both. The rendered markup follows whatever those decisions left: this one decides how markup reaches the DOM, not what it says. The timings below were taken before that rebase and have not been re-run; what they measure — a whole region rebuilt against the same region reconciled — is untouched by either decision, and the artifact size and line count are re-measured against this tree.

The decision is made on measurement, not preference. Rebuilding markup with `innerHTML` throws away DOM that did not need throwing away, and everything the interface does to compensate — restoring focus by rebuilt selector, hand-patching the attributes a re-render would otherwise redraw the grid to change, deferring a focus call a frame because its target does not exist yet — is downstream of that one cause. The evidence is recorded in [issue 12](https://github.com/tobyhede/polynome/issues/12) and the throwaway `spike/preact-preset-panel` branch.

## Consequences

- The application no longer has zero runtime dependencies. `preact` and `htm` are the only two, and the zero-dependency position becomes a default that measurement can outweigh rather than a property held regardless of cost. Adding a third still requires the justification `AGENTS.md` demands. Both are pinned to an exact version rather than a range, because a runtime dependency's code is copied into the artifacts and its version is therefore part of what ships; `test/dependencies.test.js` keeps that true.
- Rendering moves off the audio thread's critical path far enough to matter. A step click re-renders through `applyEdit`, on the same thread as the look-ahead scheduler: at the domain maximum of twelve rhythm layers on an 8/4 meter at subdivision four — 384 step controls — it cost 7.496 ms and now costs 1.992 ms, which is 30% of a 25 ms scheduler tick against 8%. The default single 4/4 rhythm layer goes from 0.566 ms to 0.226 ms. No audio defect was ever observed, because the 120 ms look-ahead absorbs a stall that size; the gain is margin, and margin is what a phone several times slower than a development machine spends.
- The preset panel gets slower and that is accepted. A tempo change with the panel open costs 0.042 ms against 0.084 ms at one Preset and 0.117 ms against 0.865 ms at a hundred, because the hand-written partial update it replaces was already tuned for exactly this path. The worst case is 3.5% of a tick, and still six times cheaper than the 5.509 ms that path cost before that tuning. A level or balance drag pays the same cost for the same reason — every pointer move clears the panel's selection too — so the figures are the panel's, not the tempo slider's.
- The single-file distribution grows from 194,762 to 211,773 bytes, 8.7%.
- `app.js` is twenty lines longer, 1340 against 1360, most of them the comments explaining the one rule reconciliation adds and the one it removes. Which is to say it is the same length. What changes is the kind of code, not the amount: focus restoration keyed to template internals, hand-proved partial updates and manual HTML escaping leave, and declarative markup arrives. `focusSelector`, `escapeHtml` and `renderPresetSelection` are deleted outright, along with all three `requestAnimationFrame` focus deferrals. The focus moves that remain are deliberate ones made after the control the user was on stopped being focusable — removed, or hidden with the menu holding it. That is the one focus case reconciliation cannot answer: a surviving node keeps focus, but a node that stops existing takes it with it.
- Preact's `render` keeps its name and the application's own whole-interface render becomes `renderInterface`. The collision is unavoidable — both are called `render` for the same good reason — and giving the imported one an alias would leave every Preact example in the documentation reading against the source.
- Interface state stays in module scope and no component owns state. This is a deliberate half-adoption and the reason is the playhead: `updateActiveSteps` toggles classes on live DOM every animation frame, and `layoutSteps` measures the DOM the renderer has just produced and writes custom properties back onto it. Under a component-owned state model both become escape hatches doing exactly what the imperative code already does, or a sixty-times-a-second reconcile that costs far more than the rebuild this decision removes. Preact is wanted for reconciliation; its state model is not.
- Writing to a rendered region by hand acquires a rule it did not have while the region was rebuilt from a string. A class or a custom property is safe: reconciliation either restores it or leaves it alone. Text is not, because `textContent` replaces the Text node rather than changing it, and Preact keeps a reference to the node it made — the readouts a level drag writes would go on displaying the last dragged value while every later render was written into a node no longer in the document. `writeReadout` changes the node's data instead, and the e2e suite asserts that the node survives the drag. Nothing today can reach the stale state, because the only other edit that moves a level replaces the whole Configuration and its identifiers with it; the constraint is recorded so that stays an accident rather than the thing holding it up.
- JSX is rejected because it needs a build step in development. `AGENTS.md` justifies esbuild solely by the two browser distribution targets, and `server.mjs` serves source unmodified. `htm` is Preact's own documented no-build path and keeps that property. Adopting a development build remains available as a separate decision with its own justification. Amended by [ADR-0018](0018-strip-types-in-the-development-server.md): the first two sentences no longer hold. esbuild has three jobs, `server.mjs` is `server.ts` and strips types from every module it serves, and development therefore has a transform step. `htm` is still Preact's documented no-build path, but the property it was kept for is one nothing here has any more, so what is written above no longer tells JSX and `htm` apart. The decision is not reopened — ADR-0018 records why — and the last sentence stands, since what that record decides is a per-file transform rather than a development build.
- Modules are resolved in development by an import map in `index.html` pointing at the installed packages, and the map is stripped from both artifacts at build time because the bundled output contains no bare specifiers. Preact's documentation warns that duplicate copies of the library cause issues, so the map names every subpath, not only the bare package.
- CDN-hosted modules are rejected even though Preact's own examples use them. The single-file distribution is opened over `file://` and must work with no network at all, which is the same constraint that had the fonts self-hosted in ADR-0003.
- Writing a keyed reconciler by hand was rejected for the reason ADR-0004 rejected a custom browser-automation harness: it duplicates a library's behaviour behind a shallow local interface, and the behaviour being duplicated here is the part that is easy to get subtly wrong.
- The change preserves behaviour, and the check is that no existing assertion had to change to keep passing — including the two that count DOM mutations to prove a region was not rebuilt, and the one that proves focus survives another tab deleting the Preset it was on. What the suites gain is coverage of what reconciliation newly makes possible to get wrong: that a drag's readout keeps the node the renderer created, and that the tag scanner in `test/accessibility.test.js` reads past a `>` inside an interpolated attribute value, which is a guard the quoted markup used to get for free. That scanner reads `app.js` as text and still finds a violation injected into an `htm` template, so it did not begin passing vacuously.
